# Submodules, subtrees, and Git LFS

The repository sidebar has **Submodules**, **Subtrees**, and **Git LFS** views. These use your system Git and existing credentials. Install `git-subtree` and Git LFS 3.x to enable their respective views; missing tools do not prevent ordinary repository use. The extension integration tests also require these tools.

- **Submodules** lists the current checkout’s direct submodules, their recorded and checked-out commits, initialization state, and local changes. Add a submodule with a URL, relative directory, and optional branch. **Initialize / update all** initializes and recursively checks out the recorded commits, including after cloning a parent repository. Each submodule also offers **Update from remote**, **Update to recorded commit**, and **Open Repository** in its own tab. **Sync URLs** applies `.gitmodules` URL changes recursively. Commit changes inside the submodule, then stage and commit its updated gitlink in the parent. Submodule diffs support whole-file staging; discard and partial staging are unavailable for gitlinks.
- **Subtrees** detects directories from `git-subtree-dir` history trailers. Add or pull from a remote name or URL and branch/tag, with optional squash; these operations create commits and require a clean working tree. Keep the squash choice consistent with the original import. Push exports committed directory history to a remote branch after showing the destination. **Split to local branch** exports the directory’s history to a new local branch. Enter an existing directory manually if it is not detected. Successful add/pull/push operations remember their remote, ref, and squash choice in local `diffinch.subtrees` Git configuration.
- **Git LFS** shows tracked patterns and files, including whether their content is downloaded and checked out. **Enable LFS in this repository** runs `git lfs install --local`, preserving existing hooks unless Git LFS can install safely. Track or untrack a pattern in the root `.gitattributes`, then review and commit it alongside the affected files. Tracking does not rewrite history or automatically convert existing blobs; re-add existing files to convert them. Fetch downloads the current ref’s objects; **Download and check out** also materializes them. **Check out cached files** works offline. Normal Git pushes use the LFS pre-push hook.

Image previews resolve LFS pointers through the local LFS cache, including custom storage and linked worktrees, with the same preview size limits as regular images. Opening a diff never downloads LFS content. Missing content is identified in the preview; fetch the relevant objects and refresh. LFS files and pointer diffs must be staged as whole files.

See the [Git submodule manual](https://git-scm.com/docs/git-submodule), [Git subtree manual](https://github.com/git/git/blob/master/contrib/subtree/git-subtree.adoc), and [Git LFS documentation](https://github.com/git-lfs/git-lfs/tree/main/docs/man) for command semantics and installation details.

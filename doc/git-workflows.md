# Git workflows

## History and comparisons

- Open **Find** in the toolbar or sidebar, or press **⌘/Ctrl+Shift+F**, to search all locally available history by commit title, description, full or partial SHA, author name/email, or branch/tag name. Search includes hidden branches, fetched remote history, and older commits beyond the graph limit. Type to search all fields automatically and optionally enable **Match case**. Results refresh when the repository's HEAD, branches, tags, or stashes change. Select a result to read its full message and diff; use **Enter/Shift+Enter** or the arrow buttons to move between matches. Results are capped at 200 (or the message size limit); narrow the query when prompted. **Find → Find changed files** opens the working-tree file filter.
- Choose **All** above **Local** and **Remote** in the left panel to open the commit graph with all local and remote branches, restoring any hidden branches. Local and Remote start expanded. Remote names and each folder formed by `/` in a branch name start collapsed. For example, expand `feature` and then `ui` to see `feature/ui/buttons`. The **Tags** and **Stashes** sidebar sections also start collapsed. Use the eye buttons to show or hide individual branches or entire folders in the graph. Shared ancestors stay visible through other visible branches, tags, and stashes; detached HEAD history remains available. Click a branch name to reveal and select its tip. Each repository remembers branch visibility and which sidebar groups you expanded or collapsed.
- Open **Commit graph** for the branch and merge graph, with local branches, remote-tracking branches, lightweight and annotated tags, every saved stash, and HEAD on their commits. Tag-only history and all stash entries (including their index and untracked-file parents) remain available when branches are hidden. The default column widths show all ref labels. Drag a divider in the header to resize adjacent columns, or focus it and use the left and right arrow keys. Each repository remembers its widths. Double-click a divider or press **Enter** to restore the default widths. The diff panel starts hidden so browsing commits does not load or render diffs. Use **Show diff panel** in the graph header to review the selected row, and **Hide diff panel** to collapse it again. **Current changes** and **Staged changes** appear above the commits when present, with file counts and a connection to HEAD. With the panel open, select either row to review its combined diff, including untracked files in current changes, or select a commit to review its diff. Search loaded commits by subject, author, SHA, or ref, or jump directly to HEAD, a branch, a tag, or a stash. The **Stashes** and **Tags** views also link to their commits. Load older commits to browse up to 2,000. Remote branches reflect locally fetched refs; fetch to update them. Tags pointing to trees or blobs have no commit to display.
- Review unified or split diffs for the working tree, index, and commit history. Stage and unstage files or individual hunks in modified text files. To discard a tracked file’s unstaged changes, right-click it in **Unstaged**, choose **Discard changes to …**, and confirm.
- Open **Compare** to compare branches, tags, or commit IDs. **Use common ancestor** shows changes made on the target since it diverged from the base. Clear it to compare the two snapshots directly. Select a file to review its patch and see its addition and deletion counts.

## Reviewing and staging changes

- Open **File history** in the workspace sidebar to browse committed files, including files with no working changes. Select a file or enter its repository-relative path; use a branch, tag, or commit in **Revision** to inspect another snapshot. History follows Git's rename detection and loads 100 changes at a time, up to 2,000; start from an older revision to continue. Deleted paths can be entered directly.
- Select a file-history commit to review its patch, or select **Blame** for line authorship at that commit. Blame uses the file's historical name, shows 300 lines per page, and supports UTF-8 text up to 2 MiB. Click a blame commit ID to open its full commit through **Find**. These views read committed content, not unsaved working edits. Reads can be cancelled and retried; results from a previous selection cannot replace the current one.
- The file menu in the working diff offers **File history**, **Open in editor**, and **External tools**. **Open in editor** always opens the current working file, even when launched from history. Missing files, directories, Git metadata, and symlink paths are rejected. See [external tools](#external-tools) for setup.

- Drag the divider between **Changes** or **Commit graph** and the source diff to resize the panes. In narrow windows, drag the divider between the stacked graph and diff vertically. Sizes are remembered separately. Double-click the divider or press **Enter** while it is focused to reset; arrow keys resize it, **Shift** makes larger steps, and **Home/End** move to the limits.
- Basic syntax highlighting recognizes JavaScript/TypeScript, JSON, CSS, Rust, Kotlin (`.kt`, `.kts`), Java (`.java`), C# (`.cs`, `.csx`), C, and C++ source and header files. Language detection works per file in combined diffs. Highlighting is line-based; search matches and word changes take priority over syntax colors.
- **Unstaged** and **Staged** have separate, collapsible panels with their own scrolling lists. Drag the divider between them to adjust their heights; the split is remembered across restarts and adapts to window height. Collapsing a panel preserves the saved split. Double-click the divider or press **Enter** to reset to equal heights; **↑/↓** resize, **Shift** makes larger steps, and **Home/End** move to the limits. Local and remote branches have separate labeled groups in the sidebar, branch picker, and **Branches** view.
- Preview PNG/APNG, JPEG, GIF, WebP, AVIF, SVG, BMP, and ICO images in **Changes**, **Commit graph**, and **Compare**. **Images** shows before and after versions on a transparency grid, with dimensions, file sizes, and Fit or 100% sizing. Added and deleted files show which version is absent. Use **Text diff** to review SVG source or other patches in the selection. Previews are limited to 10 MiB per image and 24 MiB of image data per diff; format support depends on the system webview.
- Use **Word changes**, **Ignore whitespace**, and **Find in diff** to review a patch. Click the + or − markers beside changed lines within a hunk, then choose **Stage selected** or **Unstage selected** above the diff. Switch off **Ignore whitespace** to stage hunks or lines. For truncated patches, use **Load more diff** to expand the preview up to 16 MiB.
- In the Unstaged or Staged list, use **Shift-click** or **Shift+↑/↓** to select a range, **⌘/Ctrl-click** or **Space** to toggle a file, and **⌘/Ctrl+A** to select all visible files in the focused list. Press **⌘/Ctrl+Shift+Enter** to stage or unstage the selection.

## Commits and conflict resolution

- Right-click a commit or use **Commit actions** to copy its SHA, create a branch or tag at that commit, cherry-pick, or revert. At a branch tip, the menu also offers checkout, merge, and rebase. Choose **Interactive rebase from here** on an ancestor of your current branch to reorder, pick, reword, squash, fix up, or drop the commits after it. To include the first commit, open its menu and choose **Rebase from first commit**. To edit a message, choose **Reword** on its row, edit the prefilled message, then select **Start rebase**. The editor supports up to 200 commits in a range without merge commits. Squash combines commit messages. Fixup keeps the preceding commit’s message.
- Select a conflicted text file in **Changes** to see the Git base and both index versions. Accept a side for each marked section or edit the result, then choose **Save and stage**. Continue the operation once all conflicts are resolved.
- Commit or amend with a summary, optional description, and per-commit signature. Configure author identity and signing defaults in **Repository Settings**.
- To correct an existing commit’s name or email, check out a branch containing it, then right-click the commit in **Commit graph** and choose **Change author…**. Edit the prefilled fields, review the affected commit count, acknowledge the history rewrite, and select **Change commit author**. Only the selected commit’s author changes; its descendants receive new IDs to preserve their parent links, including merges. Contents, messages, author dates, committer details, and staged or unstaged work are preserved. Other branches, tags, and remote refs are not moved. Rewritten commits lose their signatures; merge-tag signatures referring to rewritten parents are removed too. Coordinate with collaborators before publishing already-pushed history with **Force push with lease**. The old branch tip remains in its Git reflog. This action supports up to 2,000 affected commits, requires a local branch and complete history without replacement commits or grafts, and cannot run during another Git operation. The selected commit must use UTF-8 text.

## Branches, remotes, and worktrees

- Open **Worktrees** to list the checkouts sharing your repository, including their branches, commit IDs, and current, main, locked, or missing status. **Create worktree** checks out a new branch, an unused local branch, or a detached commit in a new folder and opens it in its own tab. Existing linked worktrees can also be opened with **Open repository**. Each tab keeps its own changes and index while sharing branches and history. **Remove worktree** removes a linked checkout and its tab while retaining its branch; Git refuses dirty or locked worktrees, and Diffinch protects the current and main checkout. Worktree move, lock/unlock, repair, and prune remain available through the Git CLI.
- Switch branches using the selector at the top of the left panel. The compact toolbar provides **Fetch**, **Pull**, and **Push**.
- Fetch, publish a branch, push to its upstream branch, and pull with fast-forward only. Clone and fetch show progress and offer **Cancel**. You can switch to another repository while they run. Open **Git actions** (the ellipsis next to Push) to fetch and prune stale tracking refs, pull with rebase, or rebase onto a local or remote-tracking branch. **Force push with lease** shows the destination and expected remote tip before pushing; Git rejects the overwrite if the remote branch has moved.
- Create, switch, and delete local branches, and check out remote branches with tracking. Cherry-pick or revert from history. If Git reports a conflict, fix it in your editor, stage the resolution, then continue or abort the operation from Diffinch. During a rebase, you can also skip the current commit.
- Use the delete button next to a local branch or tag to remove it. In **Branches** or **Tags**, choose **Delete remote branch** or **Delete remote tag**, then select the remote and ref to delete from its push server.
- Create, apply, pop, and drop local stashes. Manage lightweight tags and remotes.

## Long-running operations

Git actions, including push, pull, commits, signing programs, hooks, rebases, Git extensions, and merge tools, display an operation bar with elapsed time and **Cancel**. Git's progress percentages appear when available; other phases use an indeterminate indicator. The same controls remain available inside an action dialog. After 30 seconds the app suggests checking authentication, signing, hooks, or an external tool. There is no automatic timeout that could interrupt a valid long-running mutation.

Cancellation stops the Git process and its child processes where supported, including while waiting for another operation in the same repository. Diffinch then refreshes repository state without automatically retrying the command or discarding a commit draft. A cancelled command may already have changed local files, history, or a remote. Review the refreshed state, and fetch to verify a remote before retrying a push. Continue, skip, or abort controls remain available when Git reports an interrupted merge or rebase. External editors run independently and are not closed by cancelling a Git action.

## External tools

Open **External tools** from File history, the working-diff file menu, or the conflict view. Choose Visual Studio Code, Cursor, Zed, Sublime Text, or a custom executable. Preferences are saved for the app. Custom arguments are entered one per line; the working file's absolute path is appended automatically. Arguments are passed literally, without shell expansion, quotes removal, or placeholder substitution. On Windows, choose the editor's actual `.exe`; `.cmd` and `.bat` launchers are not supported. On macOS, standard installations of the preset editors under `/Applications` are detected; otherwise the executable must be on PATH or supplied as a full path.

**Open merge tool** in the conflict view invokes Git's configured `merge.guitool`, falling back to `merge.tool`, for only the selected conflicted file. Configure the tool through Git, including its path or custom command where needed. The tool must wait for the user to finish and report success through its exit code; explicitly set `mergetool.<tool>.trustExitCode` to `true`. Diffinch does not answer Git's interactive success prompts or change global Git configuration. Git's normal backup settings remain in effect.

Save or reload unsaved edits in the built-in conflict editor before opening an external tool. After a merge tool succeeds, inspect the staged resolution before continuing the merge or rebase; Diffinch does not automatically continue it. Non-text conflicts may be handled by an appropriate external tool, subject to Git's support and the same repository path checks.
